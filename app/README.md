# FaCaiBank applications

## Running the API locally

The API verifies real Cognito tokens, so local development uses a deployed user pool
(dev stack) with your local API and frontend.

```bash
python -m pip install -r app/backend_api/requirements.txt
export AWS_REGION=ap-southeast-1
export COGNITO_USER_POOL_ID=$(terraform -chdir=infra output -raw cognito_user_pool_id)
export COGNITO_APP_CLIENT_ID=$(terraform -chdir=infra output -raw cognito_user_pool_client_id)
export LEDGER_TABLE_NAME=facaibank-ledger
export KYC_STATEMENTS_BUCKET=$(terraform -chdir=infra output -raw kyc_statements_bucket_name)
export STATEMENT_QUEUE_URL=$(terraform -chdir=infra output -raw statement_jobs_queue_url)
export NOTIFICATIONS_TOPIC_ARN=$(terraform -chdir=infra output -raw notifications_topic_arn)
uvicorn app.backend_api.main:app --reload
```

RDS sits in private subnets, so the endpoints that need customer metadata (`/me`,
`/accounts`, KYC) only work from inside the VPC. For full local runs, forward the database
through Session Manager from an API instance, or test against the deployed stack. The unit
tests cover every endpoint without AWS:

```bash
python -m pip install -r app/backend_api/requirements-dev.txt
python -m pytest -q
```

On Windows PowerShell use `$env:NAME = "value"` instead of `export`.

## Frontend

```bash
python -m http.server 5173 --directory app/frontend
```

Edit `app/frontend/assets/config.js` with the user pool and client IDs, and point `apiBase` at
your API. Deployed stacks get this file generated by Terraform with `apiBase: "/api"`.

## API summary

All routes except `/health` need `Authorization: Bearer <Cognito access token>`.
Money movement needs an `Idempotency-Key` header (8–128 characters).

| Method and path | Purpose |
|---|---|
| `GET /health` | Health and deployed version |
| `GET/POST /me` | Read or create the customer profile (email comes from the verified Cognito login) |
| `GET/POST /accounts` | List or open linked accounts (up to 2 everyday and 2 savings) |
| `POST /kyc/upload` | Upload an identity document (PDF/PNG/JPG, 10 MiB); verification is simulated |
| `GET /accounts/{id}/balance` | Strongly consistent balance (owner only) |
| `GET /accounts/{id}/transactions` | Recent ledger entries (eventually consistent) |
| `POST /transfers` | Transfer to any FaCaiBank account, fraud-screened, step-up at SGD 1,000 |
| `GET /external-banks` | Mock partner banks |
| `POST /accounts/{id}/deposits` | Pull money from a partner bank |
| `POST /accounts/{id}/withdrawals` | Pay out to a partner bank (reversed atomically if declined) |
| `POST /statements/request` | Queue a PDF statement |
| `GET /accounts/{id}/statements[/{job_id}]` | List statements, or get one with a 15-minute download link |
| `GET/POST /me/alerts` | Email alert subscription status / subscribe |
| `POST /auth/logout` | Revoke the current access token |

## Background workers

Each worker runs as a systemd service on its own Auto Scaling group:

- `outbox_worker.py`: needs `LEDGER_TABLE_NAME`, `EVENTS_QUEUE_URL`, `OUTBOX_LEASE_TABLE`.
- `statement_worker.py`: needs `STATEMENT_QUEUE_URL`, `KYC_STATEMENTS_BUCKET`, and for account
  holder names and the monthly run, `DATABASE_HOST`/`DATABASE_READ_HOST`, `DATABASE_SECRET_ARN`.
